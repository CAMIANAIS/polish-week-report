# Polish Week rules (Oct 5 – 9, 2026)

Rules for me and for Claude this week. They come from the cohort lead's message:
understand what I built, apply feedback, make progress visible, own the result.

## What I'm working with
- `PLAN.md` has the tasks for each day. `README.md` is the final report.
- `daily-log/day-N.md` is where I explain problems before I fix them.
- `demo/` has the 5-minute script and the hard questions.

## Rules

1. **Apply feedback first.** Keep a list of all the feedback I got in the cohort. Each item
   maps to a task in `PLAN.md`. If feedback has no task yet, I add one, and it goes
   before any ⚪ task.
2. **Fix my regrets, not only bugs.** If a regret is "I didn't understand X," the task is
   to learn X, not only to patch code.
3. **Ask for feedback early.** When a 🔴 PR is open, I send it to a mentor the same day
   and ask: "Does this approach make sense?"
4. **Practice English every day.** For each fix, I explain it out loud in 1 minute
   (use the "Explain it" questions). I practice 3 hard questions a day and record myself
   at least once.
5. **Less, but deeper.** Five fixes I can defend beat twelve I can only describe. The
   "Never skip" list in `PLAN.md` is the core.
6. **My own voice.** The report and PR texts sound like me. Simple, honest English. If I
   can't say a sentence out loud, I rewrite it.
7. **Start with the user.** Each PR's "Problem" section starts with the person who gets
   hurt. Example: "A customer pays and gets no order."
8. **Explain before fixing.** I write the problem in my own words in the daily log
   before I change code.

## How Claude helps this week
- Teach, ask questions and quiz me. Don't write my fixes, tests or report text.
- Push me to explain *why*, and to compare options and tradeoffs.
- Keep messages short and in simple English.
- Remind me of these rules when I drift from them.

## Private material
- Mentorship transcripts and raw feedback go in `feedback/raw/`, which is in
  `.gitignore`. They have other people's words. They never go in a public repo.
- Only my own summary of the feedback (no names or private details) goes in the report.
